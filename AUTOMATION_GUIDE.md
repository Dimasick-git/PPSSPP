# Руководство по внедрению автоматизации GitHub Actions

Данный документ описывает предлагаемые механизмы автоматизации для репозитория `Dimasick-git/PPSSPP` с использованием GitHub Actions. Целью является повышение эффективности управления проектом, улучшение качества документации и оптимизация взаимодействия с сообществом.

## 1. Обзор предлагаемых GitHub Actions

Предлагается внедрение следующих GitHub Actions:

*   **Release Drafter**: Автоматизация процесса создания черновиков релизов.
*   **Issue Labeler**: Автоматическая категоризация новых задач (Issues).
*   **Stale Action**: Управление жизненным циклом неактивных задач и запросов на слияние (Pull Requests).
*   **Markdown Lint**: Обеспечение единообразия и качества Markdown-документации.

### 1.1. Release Drafter

**Назначение**: Автоматическое создание и обновление черновиков релизов на основе истории коммитов и меток, примененных к запросам на слияние. Это упрощает подготовку к выпуску новых версий, формируя список изменений (changelog) без ручного вмешательства.

**Конфигурация**: `release-drafter.yml` и `release-drafter-config.yml`.

### 1.2. Issue Labeler

**Назначение**: Автоматическое присвоение меток новым задачам (Issues) на основе ключевых слов, содержащихся в их заголовках или описаниях. Это способствует более быстрой сортировке и организации входящих запросов, улучшая навигацию и управление проектом.

**Конфигурация**: `issue-labeler.yml` и `labeler.yml`.

### 1.3. Stale Action

**Назначение**: Автоматическое выявление и закрытие неактивных задач и запросов на слияние. Это помогает поддерживать актуальность списка задач, уменьшая количество 
открытых, но заброшенных элементов.

**Конфигурация**: `stale.yml`.

### 1.4. Markdown Lint

**Назначение**: Автоматическая проверка Markdown-файлов на соответствие заданным правилам стиля и форматирования. Это гарантирует единообразие и высокое качество всей текстовой документации в репозитории.

**Конфигурация**: `markdown-lint.yml` и `markdownlint.yml`.

## 2. Инструкции по внедрению

Для активации предложенных механизмов автоматизации необходимо выполнить следующие шаги:

1.  **Создание директорий**: В корневом каталоге вашего репозитория создайте директорию `.github`, а внутри неё — поддиректорию `workflows`.

    ```bash
    mkdir -p .github/workflows
    ```

2.  **Размещение файлов конфигурации**: Скопируйте предоставленные файлы конфигурации в соответствующие директории:

    *   Файлы `release-drafter.yml`, `issue-labeler.yml`, `stale.yml`, `markdown-lint.yml` должны быть размещены в `.github/workflows/`.
    *   Файлы `release-drafter-config.yml`, `labeler.yml`, `markdownlint.yml` должны быть размещены в `.github/`.

    **Пример структуры файлов:**

    ```
    .github/
    ├── workflows/
    │   ├── release-drafter.yml
    │   ├── issue-labeler.yml
    │   ├── stale.yml
    │   └── markdown-lint.yml
    ├── release-drafter-config.yml
    ├── labeler.yml
    └── markdownlint.yml
    ```

3.  **Создание токена GitHub**: Для корректной работы некоторых Actions (например, Release Drafter, Issue Labeler, Stale) требуется доступ к API GitHub. GitHub Actions автоматически предоставляет токен `GITHUB_TOKEN` с необходимыми разрешениями для большинства операций. Дополнительная настройка не требуется, если не используются расширенные функции, требующие повышенных привилегий.

4.  **Коммит и отправка изменений**: После размещения всех файлов выполните коммит изменений и отправьте их в ветку `main` вашего репозитория.

    ```bash
    git add .github/
    git commit -m "feat: Add GitHub Actions for automation"
    git push origin main
    ```

После выполнения этих шагов GitHub Actions будут активированы и начнут работать в соответствии с заданной конфигурацией.

## 3. Дополнительные рекомендации

*   **Мониторинг**: Рекомендуется регулярно проверять логи выполнения GitHub Actions в разделе "Actions" вашего репозитория для выявления возможных ошибок или некорректной работы.
*   **Расширение**: По мере развития проекта и появления исходного кода, возможно расширение автоматизации за счет добавления CI/CD пайплайнов для сборки, тестирования и развертывания.
